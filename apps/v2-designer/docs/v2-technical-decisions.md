## 4. v2 核心技术决策（本仓库版）

### TD-001 单一坐标系原则
- 决策：编辑态统一采用 **左上角原点 + 像素坐标**。
- 约束：任何拖拽/缩放适配必须经过统一转换层，不允许在多个组件重复覆写坐标逻辑。
- 影响：避免“拖到左上角仍出现负坐标”的偏移回归。

### TD-002 图元/连线注册表单一事实源
- 决策：所有可拖拽图元 type、可切换 edge shape 必须存在于统一注册表，并可在启动时自检。
- 约束：UI 列表项不得引用未注册 shape。
- 影响：避免 `Node/Edge with name xxx does not exist` 运行时错误。

### TD-003 编辑态与发布态模型解耦
- 决策：编辑器内部继续使用 X6 JSON；新增显式转换层输出 `Schema v2.1`（`packages/core`）。
- 约束：禁止在 UI 组件中直接拼装最终发布 schema。
- 影响：降低改造成本，允许平滑迁移。

### TD-004 可恢复的交互失败
- 决策：拖拽失败、连线切换失败必须有友好提示且不丢失原对象。
- 约束：危险操作采用“先创建成功，再移除旧对象”的事务顺序。
- 影响：降低误操作损失，减少编辑器“静默失败”。

### TD-005 v2-renderer 与 v2-designer 解耦发布
- 决策：两应用独立迭代；renderer 在具备最小 schema 解析能力前，不阻塞 designer 功能上线。
- 约束：定义最小可用发布契约（画布配置、节点、边、资源引用）。

## 6. 责任边界
- `apps/v2-designer`：编辑体验、图元系统、交互可靠性。
- `packages/core`：目标 schema 类型定义与演进。
- `packages/v2-shared`：转换器、常量、校验器。
- `apps/v2-renderer`：发布态渲染与兼容性验证。

## 7. 里程碑验收标准
- M1（P0 完成）：不再出现未注册节点/连线导致的拖拽或切换崩溃；左上角拖拽坐标无负偏移异常。
